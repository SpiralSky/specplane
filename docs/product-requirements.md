# Product requirements

**Draft, for the user to finalise.** Written by the agent from decisions recorded in `HANDOFF.md` on 2026-11-06. The user owns this page: change or remove anything here.

Features cite this page. If a feature conflicts with it, stop and ask the user. A lasting user decision becomes a line here; there is no separate decision log.

## What matters

- Specplane has to work, and using it has to feel good. These come before technical preference.
- People using Specplane decide what the product does. They should not have to make technical choices to get there.

## Working with the user

- The agent makes technical choices itself and records them.
- When the agent needs a decision, it says what changes for the people using the product, the tradeoff, and what it recommends.
- Approving specs, plans and decisions stays with the user.
- Anything only the user can do is gathered into one list, so they act once.

## Trusting that it works

- "Verified" means seen working on a named version of the host, in a fresh process and a throwaway repository, with the full transcript saved. It is never judged from the working session.
- The pass condition is written before the run.

## Spending limits

- People on a subscription limit a run by the share of their usage it may reach.
- People using an API key limit a run by dollars.
