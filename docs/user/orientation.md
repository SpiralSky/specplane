# Specplane orientation

Specplane keeps what a project should do (requirements, feature specs), how it is built (architecture specs), who approved what, and the evidence that it works, as separate things. Specs are markdown in the repository; approval, test results and implementation status are records in git notes. Plans are optional and run on their own branch.

Start with `getting-started`, then `concepts`. Look up formats in `specification-format` and `plans`, settings in `configuration`, permissions in `permissions`, commands in `commands`, tests and logs in `verification`, and per-harness support in `harnesses`.

Approval is a person's decision unless the active preset gives your role `allow`; ask when a permission says `request-user`.
