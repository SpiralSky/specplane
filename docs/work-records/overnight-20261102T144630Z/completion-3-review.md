# Completion step 03 independent review

Reviewed commit `4f3f393` against the configured architecture contracts and step 03 acceptance criteria. The step is not ready to accept without fixes and focused regression coverage. This was a source review; no full suite or live calls were run.

1. **Wrong file can be updated with `--root`.** `packages/cli/src/core/completion-writer.ts:67` passes the option as `resolveSpecId`'s `fromRoot`, whose documented behavior searches the root's `extends` chain. With a spec only in base, `spec complete feature/x --root overlay` silently changes the base file. `specShowPath` explicitly qualifies an unqualified ID with the option, and feature/tooling describes `--root` as qualifying the root. Make selection consistent with show, while retaining `fromRoot` fallback for dependency edges; cover missing overlay, ambiguous names, explicit IDs, and CLI/core parity.

2. **Symlink/containment and identity are not protected.** `completion-writer.ts:56-58,86-95` reads through links and creates the temporary file beside the resolved lexical path. A symlinked directory under a spec root can cause replacement outside the checkout; a symlinked spec file is replaced by a regular file. A same-content path or symlink swap also passes the byte-only recheck. Config root validation uses `stat`, so it does not rule these cases out. Refuse unsafe links/changed path identity and check containment immediately before replacement, including dangling links and parent components. Test file and directory symlinks, swapped paths, unchanged outside targets, and safe atomic replacement. The related general config root-validation issue may also need correction; a lexical path check alone is insufficient.

3. **Mutation preconditions omit HEAD/index and stable lock errors.** Writer coordination in reference-cli requires ownership, HEAD/index and input/output digests to be rechecked immediately before mutation, and says contention returns `LOCKED`. The writer captures neither HEAD nor index; `core/index.ts:29-30` converts even `LeaseRefused` to `OPERATION_FAILED`, `retryable: false`. Capture/recheck the applicable HEAD/index state under the lease and preserve stable error codes for lock contention (and appropriate stale state errors). Add direct-edit races and assert the structured result, not only `ok: false`.

4. **Valid source presentations can be refused.** `replaceImplementation` (`completion-writer.ts:28-47`) only recognizes a column-zero simple key, although the accepted YAML parser permits other valid forms. Examples include an indented root mapping, explicit mapping keys, or an anchor on `implementation` subsequently referenced by another field (rewriting drops the anchor and validation fails). This is not limited to invalid metadata: complete and status commands are required for valid records. Use a source-aware edit that preserves unrelated source/semantics, and test valid variants, aliases, comments, delimiters, CRLF, and lifecycle/body bytes. Ensure unrelated parsed metadata remains exactly unchanged after an edit as well as validating the proposed schema.

5. **Acceptance coverage is incomplete.** The two writer tests do not inject mutations between capture and preimage checks. Add deterministic tests independently changing config, an existing or missing resolution candidate, root, transitive dependency, index/HEAD, and lease ownership; assert refusal, preservation of the concurrent edit, body/lifecycle, unrelated dirty files, and index, with no leftover temp file. Exercise actual `spec.complete` and `spec.implementation` through both CLI and core for every status, dry run, no-op, preserved evidence and representative refusal; the current test compares only one CLI fingerprint against one core preview and never checks lock error identity. Test dry-run side effects across the Git common runtime location, including linked worktrees. Existing completion graph unit tests support the underlying closure algorithm but do not establish these writer guarantees.

The basic code does preserve previous evidence and historical assessments, computes the transitive closure for complete, checks digests of resolution candidates it reads, avoids a lease during dry-run, and uses a same-directory rename. Those observations do not establish the race, path safety, and preservation guarantees above.
