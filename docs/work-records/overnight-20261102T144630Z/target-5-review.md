## Findings requiring repair

1. **Destination ref snapshot can validate a different commit from the one rechecked.** `packages/cli/src/plan/retarget.ts:126-128` resolves `destination.targetCommit` by reading target refs, then captures those refs separately. A direct Git update between these reads causes plan identity, lifecycle, dependencies and spec checks to use the prior commit while `recheckLifecycleRefs` sees the later captured ref values as unchanged and allows the metadata write. Capture before resolution and derive the selected commit from those captured values, or verify resolution against that snapshot and retry/refuse on change. Add a deterministic interleaving regression that moves a destination ref after resolution but before capture and confirms refusal without mutation.

2. **Explicit GitHub forge can silently skip required evidence.** At `retarget.ts:165-171`, an absent `origin` skips the entire evidence check, including when `plans.forge: github` explicitly requires GitHub and its unavailability must fail (reference-cli forge contract). This can return a successful preview and write without required PR evidence. Refuse when GitHub is explicitly configured but unavailable; test both dry-run and actual operation in a no-origin repository and verify no plan write. Existing no-origin default-auto fixture does not cover this.

3. **Human preview omits required context.** `packages/cli/src/cli.ts:53` only prints old/new and a preview label; reference-cli requires preview to include original starting context and records to change. It omits start branch/base, comparison baseline and changed file, even though the receipt has them. A no-op dry-run also prints `unchanged` without the required warning that refs may change. Render these fields and advisory for changed and no-op previews, with CLI-level assertions.
