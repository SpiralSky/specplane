signal, no code) to `unknown`, never `failed` (session-adapter.ts stateOf; the null-exit case near the end of the observe test in claude-session-adapter.test). The probe driver
passed the `code` of node's child_process 'exit' event, and `failed` is only returned for a non-null, non-zero code, so the real
process exited with a numeric non-zero code after SIGTERM (the `claude` CLI handles the signal and exits itself), not by signal. The
exact code was not logged and the driver's stdout was not kept, so it is unknown. The code agrees with A13; no live run was done to check.
